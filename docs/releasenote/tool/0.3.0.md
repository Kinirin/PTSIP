# PTSIP Reference Tool 0.3.0 Release Notes

**Status:** Source merged to `main`, not published/tagged  
**Release tag:** none  
**Bound Specification:** `0.2.0-draft` revision `a877b2f66a7f94c1b844c979e1b08fb08a9a8e45`

Tool 0.3.0 is the conformance-capability expansion built from the Tool 0.2.3 evidence-correctness baseline.

## Conformance and diagnostics

- added `ptsip conform` with deterministic `CONFORMANT`, `NON_CONFORMANT`, and `INCOMPLETE` outcomes and distinct CLI exit codes;
- emitted stable `ptsip-diagnostic/v1`-shaped diagnostics with diagnostic-instance identity separate from PTSIP rule identity;
- evaluated rule-relative blocking evidence coverage rather than treating empty findings as conformance;
- performed a final conformance-report audit against the embedded diagnostic schema, active rule registry, applicability/evidence sufficiency, coverage-gap identity, and evaluator-state contract before allowing `CONFORMANT`;
- kept `ptsip pilot` at `conformance.status=NOT_EVALUATED`; strict outcomes are produced only by `ptsip conform`.

## Product Artifact, build, and lifecycle evidence

- accepted explicit read-only `ptsip-artifact-evidence/v1` inputs and evaluated Product packaging isolation without conflating artifact producer and artifact owner;
- bound artifact evidence through a Tool-level sidecar carrying the imported document SHA-256 and exact Consumer Repository revision/tracked-content identity without extending the canonical artifact schema;
- added independent build-resolution evaluation over declared component manifests for Python, npm, .NET, and Go while blocking ambiguous cross-plane shared-manifest evidence;
- added lifecycle evaluation that requires declared release/compatibility ownership plus positive path-scoped release evidence and does not treat workflow triggers alone as sufficient proof of coupling or independence.

## Dependency evidence expansion

- added deterministic JavaScript/TypeScript source dependency evidence for static imports, CommonJS `require`, and dynamic import/require uncertainty;
- recognized executable dependency expressions inside JavaScript/TypeScript template-literal interpolation regions;
- added npm manifest evidence for runtime/build dependency declarations and local package-to-package resolution;
- added Go source/module evidence with local-module, standard-library/platform, and external-module scope resolution;
- added source-level .NET `using` evidence that resolves local project identity only when corroborated by `.csproj` `ProjectReference` metadata;
- used comment/string-aware lexical scanning for Go, JavaScript/TypeScript, and C# source dependency statements;
- routed `inspect`, `pilot`, `clarify`, and `conform` through one composite dependency evidence graph;
- preserved native `DYNAMIC` uncertainty instead of allowing sentinel-only external evidence to clear it.

## Project policy and imported evidence

- evaluated optional project-specific component dependency policy separately from universal PTSIP diagnostics, consistent with `PTSIP-POL-001`;
- ingested bound-schema agent classification decisions as review evidence without allowing them to overwrite Project Profile declarations;
- accepted explicit `ptsip-external-evidence/v1` dependency evidence only when producer metadata and Consumer Repository identity/revision can be verified;
- preserved imported-file SHA-256 and canonical provenance;
- allowed trusted observed external evidence to supplement bounded native unresolved evidence while blocking contradictory resolved external/native evidence;
- prevented inferred external evidence from clearing native uncertainty;
- blocked unsupported mandatory-relevant source ecosystems, ambiguous release-like workflows, and ownership-incompatible build manifests when they could conceal an applicable mandatory-rule result.

## Regression boundaries

- retained Tool 0.2.2 Human Clarification deterministic zero-LLM semantics;
- retained Tool 0.2.3 evidence-correctness behavior;
- deliberately preserved uncertainty: stale, contradictory, unresolved, incomplete, ambiguous, or unstable evidence blocks `CONFORMANT` instead of being silently ignored.
