# PTSIP Tool 0.3.8a3

## Purpose

Tool `0.3.8a3` is an urgent patch for migration semantics omitted from the published Tool `0.3.8a2` transition to the canonical repository-local `.ptsip/` control plane.

The patch removes the ambiguous state in which a coding agent could stop reading `MEMORY.md` before a valid Context Plane exists, delete the legacy file too early, or hand-edit generated Context projections without a canonical semantic source.

It also fixes a distribution-boundary defect in the published `0.3.8a2`: the Context Projection implementation existed only at `developer/automation/context_projection.py`, while package discovery ships from `src/` (`ptsip*`, `vpms*`, `agent_contracts*`). As a result, an installed `PTSIP==0.3.8a2` could not own that Context Projection implementation as a Consumer Tool capability. `0.3.8a3` promotes the canonical implementation to `src/ptsip/context_plane.py` and keeps the developer entry as a compatibility wrapper.

## Added

The installed Tool now exposes:

```text
ptsip context status . --json
ptsip context migrate . --input <prepared-context-source.json> --json
ptsip context repair . --json
ptsip context check . --json
```

`status` returns machine-readable state and coding-agent authorization. Deterministic projection repair is preauthorized. Semantic selection is not.

## Consumer distribution correction

The `0.3.8a3` wheel and sdist must contain the shipped Context Plane implementation.

```text
wheel:  ptsip/context_plane.py
sdist:  src/ptsip/context_plane.py
CLI:    ptsip context status|migrate|repair|check
```

Distribution verification treats these as required release contents, and the exact-SHA prerelease workflow reinstalls the built wheel before exercising the `ptsip context` surface. Repository-only availability under `developer/automation/` is not sufficient for release.

## Migration semantics

- `.ptsip/context/source/context.source.json` is the semantic source of truth.
- `.ptsip/context/context.json`, `.ptsip/context/context.jsonl`, and `.ptsip/context/context.schema.json` are generated projections.
- If `MEMORY.md` exists and no canonical source exists, the agent may read it only for migration and prepare a canonical source input.
- A deterministic conversion may proceed without another user question. Any semantic ambiguity or conflict requires the project owner to decide.
- Replacing an existing canonical semantic source requires explicit user approval.
- `MEMORY.md` is deleted only after the source and every mandatory projection pass Context validation. A failed migration preserves the legacy file.
- Missing or drifted projections are regenerated deterministically from the canonical source without user confirmation.
- Direct projection editing remains forbidden during normal operation. Emergency direct edits require explicit user approval and are temporary only.
- Release is blocked until generated projections are reconciled from the canonical source and `ptsip context check . --json` passes.
