# PTSIP Reference Tool 0.3.1 Release Notes

**Status:** Current source version, not yet published/tagged  
**Expected release tag:** `tool-v0.3.1`  
**Bound Specification:** `0.2.0-draft` revision `a877b2f66a7f94c1b844c979e1b08fb08a9a8e45`

Tool 0.3.1 adds a Tool-level, non-normative human architecture-decision control plane while retaining Tool 0.3.0 conformance semantics and the same immutable Specification binding.

## Coding-agent decision gate

- added `ptsip gate` for **on-demand** coding-agent checks only when an active boundary-sensitive task actually needs a missing human architecture decision;
- deliberately added no timer, scheduled reminder, background polling, or overdue-notification worker;
- creates or reuses a GitHub clarification Issue through the configured GitHub App-backed control plane when a required decision is unresolved;
- added explicit user-authorized `ptsip resolve` so a coding agent can record a decision supplied in the active chat and safely project it into `ptsip.yaml`;
- supports asynchronous Issue-originated decisions through the fixed `ptsip-clarification-answer/v1` YAML contract;
- keeps free-form Issue prose outside deterministic classification and does not interpret it with an LLM.

## Decision correctness and concurrency

- expanded deterministic clarification facts to include classification, purpose, shipping, runtime role, lifecycle owner, and executable/non-executable role;
- added deterministic consistency checks for Product, Toolchain, and Neutral Contract decisions;
- validates projected profiles before a candidate answer can become authoritative;
- preserves existing component IDs, selectors, and already-declared facts when filling a partial declaration;
- stores authoritative workflow state separately from the Consumer Repository declaration;
- uses compare-and-set semantics so the **first valid resolution wins**;
- ignores later contradictory chat or Issue answers after a decision is terminal;
- closes/completes the linked Issue after an accepted decision is successfully applied;
- reopens a manually closed still-pending Issue only when a later active gate actually needs that decision.

## GitHub App reference control plane

- added an HTTP agent API, webhook receiver, SQLite workflow store, GitHub App installation authentication, Issue management, and repository-write support;
- verifies GitHub webhook payloads with `X-Hub-Signature-256` HMAC SHA-256 before accepting Issue events;
- accepts Issue decisions only from repository users with accepted write-level authority;
- recovers missing repository-to-installation mappings on demand from the GitHub App API instead of depending on a background reconciliation worker;
- binds Issue-originated profile application to the exact recorded branch revision;
- updates the branch through an exact-parent, non-force Git ref change so stale decisions are not silently applied to a changed branch;
- allows an active gate to rebind only the application target of an already authoritative stale/failed decision, so the stored answer can be retried without asking the user to decide again;
- keeps `ptsip clarify --publish github-issue` as a manual/offline fallback.

## Packaging and release engineering

- added the optional `github-app` package extra and `ptsip-app` reference-service entry point so ordinary local Tool installations do not require GitHub App cryptographic dependencies;
- introduced `git-cliff`-based versioned release notes under `releasenote/` and an on-demand release-preparation workflow;
- preserves the existing `tooling-release.yml` PyPI Trusted Publishing boundary so publication still occurs only from an explicitly published `tool-v*` GitHub Release;
- excludes repository `tests/` from the source distribution through `MANIFEST.in`;
- verifies during the release build that both wheel and sdist exclude `tests/` before `twine check` and publication.

## Documentation and regression boundaries

- updated the coding-agent operational contract and added [`reference/DECISION-CONTROL-PLANE.md`](../reference/DECISION-CONTROL-PLANE.md) as the Tool-level workflow reference;
- retains Tool 0.3.0 conformance outcomes, evidence coverage, diagnostic contracts, and multi-language evidence adapters;
- retains Tool 0.2.2 deterministic Human Clarification as a regression boundary;
- consolidates historical Tool and Specification change records into versioned documents under `releasenote/` rather than maintaining root-level changelog files.
