# PTSIP Tool


Emergency PTSIP Package **0.3.8b4** includes Validation engine **0.3.2** with
capability contract **3.1.0**. Profile pp.1.02, Context/Projection 0.2.1 and
Storage/Discovery/Planning/Execution 0.3.1 retain their independent versions.

Validation automatically connects external `$ref` URIs to `$id` values in the
explicitly supplied local `schema_resources` set. Callers provide schema contents;
the engine builds the identifier index. Relative and transitive external
references and fragments in a different resource are supported.

**Internal `$ref` and `$dynamicRef` are unsupported.** The engine now names these
limitations explicitly in errors and `ptsip-engine-validation --help`. It does
not download schemas or scan the filesystem. See the
[support table and request example](https://github.com/Kinirin/PTSIP/blob/codex/validation-b4/docs/validation-schema-references.md).

Only **PTSIP** is published to PyPI: one complete Windows x64 wheel, one complete
Linux x64 wheel and one sdist with all Rust sources and lockfiles. Each wheel
contains the Tool, public Profiles and all seven engines. Linux source rebuild
and fresh installation remain mandatory before publication. Installation does
not grant runtime activation or PTSIP conformance authority.

The bounded hotfix branch is `codex/validation-b4`, derived from the published b3
branch. Historical releases are preserved and this work does not merge to main.
Software verification does not stand in for the retired Developer Policy Resolver.


# Project Profile pp.1.02


State: Current Project Profile contract
Transition: pp.1.01 -> pp.1.02 / SEMANTIC_MIGRATION
Specification binding: 0.3.7-draft @ 3c47816770d194ae42f98faedc911d980db0e62a

### Purpose

This contract separates developer-owned Project Profile generation from
user-owned profile lineage and removes path-shaped examples that could be
misread as repository architecture authority.

### Contract changes

- ptsip.revision is now required and uses canonical Rev.#### form.
- Developer-distributed baselines begin at Rev.0001.
- ptsip.specification.family is no longer serialized in current Project
  Profiles. Specification identity remains exact through source plus the
  immutable Git revision.
- ptsip.profile_role distinguishes repository authority (PROJECT) from
  distributed examples (DISTRIBUTED_EXAMPLE).
- Distributed examples require project-path materialization and must not be
  treated as canonical repository layout.
- New repository-local profile storage uses .ptsip/profiles/index.yaml with
  an explicit default_profile and one or more *.ptsip.yaml resources.
- New adoption defaults to .ptsip/profiles/main.ptsip.yaml.
- Repository-root ptsip.yaml remains a compatibility/migration input rather
  than the default target for new profile creation.

### Example-path safety

Public examples use unresolved project-owned selector placeholders instead of
prescribing paths such as product/app/** or a developer's private tooling
layout. A project or agent must resolve those selectors against repository
evidence and explicit project authority before materializing a PROJECT profile.

### Authority boundaries

This Project Profile transition does not change the frozen Specification
family or its immutable revision. It also does not rewrite historical Tool
release notes. Tool SemVer, Project Profile contract identity,
ptsip.revision, and Specification revision remain separate axes.

## Validation 0.3.2

Engine ID: `urn:uuid:44258a79-af23-4ce9-94c9-6d23de29bd21`
Capability: `urn:uuid:450659b1-1e89-4138-91d3-8dcbf6d6dc1a`

### Purpose

Validate schemas, contracts, typed I/O, preconditions and Cases through five
independent operations, or combine checks with `validation.compose`. The separate
handoff and case-preparation operations retain their registered responsibilities.

### Contract changes

Capability contract **3.1.0** adds optional `schema_resources` to the five generic
validation operations and to the top level of `validation.compose`. The engine
automatically indexes the supplied schemas' `$id` values and connects external
`$ref` targets. Relative external references, transitive references and fragments
in a different registered resource are supported. Embedded schema resources with
their own `$id` are also indexed.

**Internal `$ref` (`#`, `#/$defs/...`, or an absolute self-reference) and
`$dynamicRef` remain unsupported.** They fail explicitly with
`INTERNAL_REF_UNSUPPORTED` or `DYNAMIC_REF_UNSUPPORTED`. Missing resources and
duplicate IDs fail closed. There is no network retrieval or automatic filesystem
search. Callers supply the JSON contents of permitted local schemas.

See the [reference support table and complete request example](https://github.com/Kinirin/PTSIP/blob/codex/validation-b4/docs/validation-schema-references.md).
The previous 3.0.0 contract is retained as historical data; requests must select
the current exact engine and contract versions. Outputs still do not assert PTSIP
conformance or grant execution authority.

PTSIP 0.3.8b4 embeds Validation 0.3.2 and all six other engines in each complete
Windows x64 and Linux x64 wheel. Only the PTSIP project is published to PyPI.
