# PTSIP Reference Tool 0.3.2 Release Notes

**Status:** Migration source, not yet merged/published/tagged  
**Expected release tag:** `tool-v0.3.2`  
**Bound Specification:** `0.2.0-draft` revision `a877b2f66a7f94c1b844c979e1b08fb08a9a8e45`

Tool 0.3.2 adds Tool-level repository topology refactoring while preserving the existing PTSIP architecture classification model and the same immutable Specification binding.

## Topology migration

- added `ptsip topology` to plan repository component-root rename/move operations;
- dry-run is the default and reports the source/target root, selected component, preserved classification, affected profile declarations, and tracked source files;
- `--apply` is required before the Tool modifies repository topology;
- component-based profiles require an explicit `--component` so a root move is never treated as an implicit architecture ownership decision;
- boundary-root profiles preserve the owning Product, Toolchain, or Neutral Contract classification while changing only the declared root path;
- the projected profile is schema-checked before application and validated again against the post-move repository state;
- Git repositories require a clean working tree/index for `--apply`; the move uses `git mv` so tracked-file evidence immediately follows the new root;
- classification maps are compared before and after projection and application. A migration that changes classification is rejected.

Example dry-run:

```powershell
ptsip topology . `
  --profile docs/sdk/simple-connection.ptsip.yaml `
  --component sdk-tools `
  --from src/sdk `
  --to src/tooling/sdk `
  --json
```

After reviewing the plan, explicitly apply it with the same arguments plus `--apply`.

## Reference impact analysis

The migration plan scans tracked text files for references to the old root and reports them by impact class:

- `PROFILE`
- `IMPORT`
- `BUILD`
- `CI`
- `DOCUMENTATION`
- `OTHER`

Tool 0.3.2 does not blindly rewrite those non-profile references. `--apply` performs the deterministic root move and Project Profile path rewrite, then reports remaining references for manual review. This avoids changing historical documentation, build semantics, or source imports merely because they contain the same path text.

## Explicit profile path for resolution

`ptsip resolve` now accepts `--profile <path>` and uses that path for local profile projection and write-back instead of always forcing repository-root `ptsip.yaml`.

This aligns local resolution with the explicit profile-path handling already available to `ptsip validate` and `ptsip conform`, including repositories such as Simple Connection that keep their PTSIP declaration under a project-owned path such as `docs/sdk/simple-connection.ptsip.yaml`.

If `--profile` is omitted, the existing repository-root `ptsip.yaml` default remains unchanged.

## Regression boundary

Tool 0.3.2 does not change:

- the three PTSIP architecture classifications (`PRODUCT`, `TOOLCHAIN`, `NEUTRAL_CONTRACT`);
- conformance outcomes or mandatory-rule semantics;
- the Tool-bound Specification revision;
- first-valid-resolution-wins decision semantics;
- deterministic Human Clarification behavior;
- PyPI Trusted Publishing release boundaries.

The topology feature is Tool-level refactoring support. A successful topology migration does not itself claim a new PTSIP conformance outcome; normal `validate`/`conform` evaluation remains authoritative for those results.
