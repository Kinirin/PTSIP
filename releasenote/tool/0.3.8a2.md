# PTSIP Tool 0.3.8a2

## Purpose

Tool `0.3.8a2` is an urgent repository-namespace stabilization prerelease.

The immediate goal is to stop Consumer Repositories and coding agents from inventing incompatible PTSIP-owned Task, Policy, Operation, registry, and runtime locations such as `tools/ai_interface_tool/` or `tools/policy_engine/` merely because a complete generic Task Engine is not yet available.

## Added

- `.ptsip/` is established as the canonical repository-local ownership boundary for PTSIP-managed machine contracts, registries, configuration, task/operation metadata, and execution state.
- `.ptsip/index.json` is introduced as the canonical repository namespace routing entry point.
- Canonical repository namespace indexes use JSON.
- `.ptsip/profiles/index.json` replaces the pilot YAML form for new/canonical local Project Profile selection.
- `.ptsip/tasks/index.json` reserves the Task namespace and explicitly reports the generic Task Engine as unavailable rather than leaving agents to infer a new implementation location.
- `.ptsip/runtime/` is reserved as the repository-local runtime namespace without prematurely freezing its final persistence semantics.
- New local-profile materialization creates the canonical root index and JSON profile index together with the selected profile.

## Compatibility and migration

The former `.ptsip/profiles/index.yaml` catalog remains readable as compatibility-only migration input in Tool `0.3.8a2`. New writes do not emit it. A repository must not contain both canonical `index.json` and legacy `index.yaml` local-profile indexes at the same time.

Repository tooling implementation code may remain outside `.ptsip/`. This release standardizes the location of PTSIP-owned registration, policy bindings, task/operation contracts, indexes, and lifecycle state; it does not require executable project tooling itself to move under `.ptsip/`.

Read-only inspection and Pilot operations remain read-only and do not create repository state merely by being invoked.

## Task Engine and language boundary

This release does **not** claim a complete generic Repository Task Engine, public `task audit/plan/apply/recover` surface, arbitrary repository file task execution, or Go runtime.

The approved longer-term migration direction remains language-neutral machine contracts with a cross-platform Go Task Runtime while preserving validated Python behavior through explicit compatibility boundaries. That larger migration is intentionally non-blocking for this urgent prerelease.

This Tool prerelease does not introduce a new Specification family or Project Profile contract.

## Release boundary

Publication requires full exact-SHA repository verification on the final `dev/0.3.8` release commit, successful release-contract and distribution verification, and publication of tag `tool-v0.3.8a2` pointing to that exact verified commit.

The prerelease is intentionally published without merging the continuing `dev/0.3.8` development line into another development-version branch.
