# PTSIP Tool 0.3.8a1

## Purpose

This is an emergency demo/prerelease bridge for projects blocked because PTSIP cannot yet formally represent a component that does not exist as a proposed candidate before that component is created.

The release is intentionally narrow. It is not the completion of Tool 0.4.0 and must not be treated as providing unfinished 0.4.0-only capability-recovery or resolution semantics.

## Added

- A supported path for representing a not-yet-existing component as an explicit proposed candidate.
- Machine-readable candidate identity and resolution flow for that proposed state.
- Fail-closed handling for malformed, ambiguous, or unsupported candidate registration input.
- Explicit separation between proposed candidate representation and an actually existing/materialized component.

## Authority and safety boundaries

- Registering or discovering a proposed candidate does not create project intent.
- A proposed candidate does not become Project Authority merely by being registered.
- The feature must not silently materialize the proposed component as already existing.
- Unsupported use blocks only the dependent operation and must not block unrelated normal development.

## Scope

This prerelease exists to unblock development while the broader 0.4.0 architecture continues.

The following are intentionally not claimed by this release:

- completion of the 0.4.0 Capability Recovery model;
- finalization of provisional S3 execution-record shapes;
- general support for every future component-creation or recovery workflow.

## Release gate

Publication is allowed only after the not-yet-existing-component proposed-candidate feature is implemented, focused success/fail-closed tests pass, relevant regression tests pass, and the exact current `main` SHA has a successful `self-hosted/tooling-test` status.
