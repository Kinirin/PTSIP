# PTSIP Reference Tool 0.2.3 Release Notes

**Status:** Source-only migration, intentionally not published  
**Release tag:** none  
**Bound Specification:** `0.2.0-draft` revision `14a0c2f54bb486de6a109979224f998b04fd04a3`

Tool 0.2.3 was an evidence-correctness migration used as the implementation baseline for Tool 0.3.0. It was intentionally not released to PyPI and received no `tool-v0.2.3` tag.

## Changes

- used Python source encoding detection so UTF-8 BOM and valid source encoding declarations do not become false read failures;
- resolved relative Python imports deterministically when package/repository evidence identifies the target;
- separated evidence-node scope into `PROJECT_COMPONENT`, `EXTERNAL_DEPENDENCY`, `PLATFORM`, and `UNRESOLVED_TARGET` without expanding the three PTSIP architectural classifications;
- recorded dependency provenance independently from target scope;
- represented dynamic Python imports as `LOADS`, retaining `DYNAMIC` resolution when the target is not statically known;
- recognized direct declared Python dependencies as external evidence when declaration/import naming matches deterministically;
- resolved GitHub Actions local scripts from the effective workflow/job/step `working-directory`;
- stopped converting arbitrary GitHub Actions `run:` commands into unresolved local-script invocation edges;
- reported declared dependency evaluator state as `RAN` or `BLOCKED` so `findings: []` cannot imply an evaluator ran when it did not;
- synchronized embedded profile schema and registry resources to the Tool-bound immutable Specification snapshot;
- aligned Project Profile validation with `boundaries XOR components`, retired mandatory-rule waiver semantics, exact revision binding, and project component-policy references;
- retained Tool 0.2.2 deterministic Human Clarification behavior as a regression boundary;
- deliberately did not add `ptsip conform`, Product Artifact adapters, JS/TS/npm/Go adapters, stable diagnostic emission, agent-decision ingestion, or external evidence import.

## Publication policy

Tool 0.2.3 remains a source-only historical version. Its implementation became the direct baseline for Tool 0.3.0 rather than a separately published package release.
