# PTSIP Tool 0.3.8a4

## Purpose

Tool `0.3.8a4` consolidates the developer control plane and release verification work completed after `0.3.8a3`. It moves repeatable developer-side reasoning and verification toward native Go automation, strengthens Root Family policy lifecycle enforcement, and makes release preparation and publication use one canonical workflow surface while preserving independent phase verification.

This prerelease does not introduce a new PTSIP Specification family or Project Profile contract.

## Developer automation

- Developer automation has been migrated toward the native Go `ptsip-dev` control surface.
- Retired Python developer-automation paths are not restored as compatibility authorities.
- Policy responsibility analysis uses the registry-first machine path and current Root Family authority rather than re-deriving authority from legacy layout.
- Current Root policy validation is separated from historical reconstruction so historical artifacts do not become runtime authority.

## Project Profile and repository control plane

- The repository Project Profile is selected from `.ptsip/profiles/main.ptsip.yaml`.
- Distributed Project Profile resources are consolidated under `src/ptsip/profiles/`, with historical baselines retained for source verification and excluded from wheel runtime content.
- Project Profile transition verification checks every introduced commit in the relevant merge range and remains exact-SHA, verify-only behavior.

## Release and verification

- `.github/workflows/tooling-release.yml` is the single release management surface.
- PREPARE and PUBLISH remain separate lifecycle responsibilities and independently verify their exact source.
- Release readiness verification is split into Go responsibility units under `developer/tests/release/` for identity, gate, workflow, contract binding, distribution, and publication artifact behavior.
- The `repository-release` Test Mode routes to the Go release verification surface.
- Test Mode resolution supports Go-only verification targets without requiring a synthetic pytest target.

## Preserved compatibility

The `0.3.8a3` Consumer Context Plane behavior remains available, including `ptsip context status|migrate|repair|check`. Historical `0.3.8a3` Context migration records remain historical records and are not rewritten as `0.3.8a4`.

## Release boundary

Publication requires the exact-main release preparation gate, successful policy/PRA/Project Profile verification, the Go release verification responsibilities, release-contract and distribution checks, exact Product Artifact evidence/snapshot binding, and PyPI Trusted Publishing through `tooling-release.yml`.
