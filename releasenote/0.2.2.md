# PTSIP Reference Tool 0.2.2 Release Notes

**Status:** Historical source version, not published  
**Release tag:** none

Tool 0.2.2 introduced deterministic human clarification for missing architectural intent while remaining bound to the existing `0.2.0-draft` Specification family and its immutable Tool-bound revision.

## Changes

- added `ptsip clarify` so missing architectural intent stops at an explicit question instead of expanding speculative classification inference;
- kept clarification analysis deterministic and model-free, with machine-readable output reporting `llm_calls: 0`;
- added fixed English (`en`) and Korean (`ko`) clarification question templates;
- made language selection follow explicit `--lang`, then `PTSIP_LANG`, then the operating-system locale, with English fallback;
- added Git `origin` discovery and deterministic GitHub HTTPS/SSH normalization to `owner/repository`;
- added explicit `--publish github-issue` transport with optional `--repo owner/repository` override;
- required the external authenticated `gh` CLI only when GitHub publication is explicitly requested;
- stored duplicate-publication state under external `PTSIP_HOME/clarifications`, outside the Consumer Repository;
- kept ordinary clarification read-only against the Consumer Repository;
- did not collect, interpret, or automatically classify free-form Issue answers;
- retained the existing `0.2.0-draft` Specification identity; this Tool capability did not change normative PTSIP semantics or schemas;
- kept the later evidence-correctness and conformance work separate for Tool 0.2.3 and 0.3.0.

## Historical role

Tool 0.2.2 is retained as the deterministic Human Clarification regression boundary. Later Tool versions may extend the decision transport and explicit user-authorized resolution workflow, but they must not silently turn free-form prose into architectural truth.
