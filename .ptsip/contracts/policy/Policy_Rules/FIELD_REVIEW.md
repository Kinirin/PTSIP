# 신규 계약 필드 검토

현재 단계는 `FIELD_REVIEW`다. 사용자 지시에 따라 생성한 신규 계약 후보이며,
현재 `.ptsip/index.json`, `contracts/index.json`, 정책 boundary와 개발자 검증기의
선택 경로에는 연결하지 않았다. 이 묶음에는 검증기나 평가 실행 구현이 없다.

검토 진입 파일은 `../candidate.index.json`이다. 이 파일은 스키마, 원본 바인딩,
Family 선택 후보, 입력을 모두 거부하는 미정 골격, 기존 소유 계약 참조를 구별한다.
신규 `$id`는 `urn:ptsip:candidate:contract:`를 사용하며 기존 식별자를 대체하지 않는다.

## 위치와 기존 계약의 공존

요청한 25개 경로를 그대로 생성했다. `Plans/PTSIP_Public_Policy_Structure.schema.json`도
요청한 파일명 그대로다. 기존 계약, 정책 라우팅, Family 규칙, 정책, 프로필과 검증기는
생성 직전 스냅샷으로부터 변경하지 않았다. 기존 정책·프로필의 미커밋 수정 2건은
이 묶음 생성 전 작업이며 그대로 보존한다.

원본 바인딩 JSON 2개는 기존 식별·권한 자료의 경로와 내용 해시를 참조한다.
원본 자료를 복제하거나 독립 등록부로 승격하지 않는다. 식별·생명주기·프로필 Storage·RBAC의
변경하지 않은 제약은 명시된 기존 소유 계약을 참조한다. 이 참조 파일 생성은 이전 완료를 뜻하지 않는다.

## 공통 필드 후보

| 소유 단위 | 필드 | 역할 |
|---|---|---|
| Policy_Rules | contracts | 계약별 블록. 네 중간 구획을 필수로 반복하지 않음 |
| 계약 | contract_id, Rule_ver, rules | 계약 식별, 자체 규칙 버전, 명시된 규칙 목록 |
| 규칙 | id, rule, requirements | 기존 R-ID, 등록된 규칙명, 개별 요구사항 |
| 규칙·요구사항 | target_refs, preconditions, excluded_target_refs, reserved_responsibility_refs | 해당 항목이 직접 소유하는 범위. 묵시적 상속 없음 |
| 요구사항 | responsibility_refs, meaning_ref | 책임의 직접 연결과 안정적인 원본 항목·리비전 |
| 요구사항 | relation_ref | 적용할 조합 계약의 선택 참조 |
| 요구사항 | evidence_requirement_refs, judgement_ref, decision_refs | 증거 요건, 원본에 근거한 명시적 판정, 결정 출처 |
| 계약 선택 참조 | contract_ref, compatibility_ref, selection_rule_ref | 승인된 호환 범위 근거와 결정적 선택 규칙의 참조 |
| 원본 참조 | source_ref, item_ref, revision_ref | 정확한 원본 항목과 리비전. 문장 유사성·배열 순번으로 식별하지 않음 |

세부 필드명·필수 여부·개수 제약은 검토 대상이다. 원본 참조 문법과 실제 등록된
호환·선택 계약은 미정이다. 비어 있지 않은 문자열이라는 검사로 참조 해석이나 권위를
입증하지 않는다. SemVer, 최신 버전 우선, 역할 추론, Family 이름 기반 선택을 추가하지 않았다.

## 관계와 조합의 경계

역할 연계·공동 충족·선택 충족·결과 의존·선후 관계를 독립 후보 스키마로 구별한다.
영문 유형 값과 후보 스키마 ID는 검토용 직렬화이며 등록된 실행 코드가 아니다.
공동 충족은 지정된 적격 결과를 소비하며, 선택 충족은 원본이 허용한 대안 중 하나 이상이다.
배타적 선택·투표·가중치·자동 대체를 포함하지 않는다. 결과 의존은 특정 출력·입력,
선후 관계는 특정 사건을 다룬다. 스키마 통과로 원본의 관계 허용을 입증하지 않는다.

조합은 기본 관계, 명시적 조건부 관계, 참여 책임 바인딩을 선언한다. 조건에는 원본 근거가
필요하며 미확인 조건을 적용 제외로 처리하지 않는다. 전체 적용 관계의 결과·불성립·미확인
근거를 보존한다. 조합 자체가 요구사항 충족이나 권한을 부여하지 않는다.
조합 중첩·스케줄링·재시도·충돌 해결의 기본 알고리즘은 정의하지 않았다.

## 독립 평가 기록

Evaluation_Record는 공통 문맥 한 개, 선택 근거와 정확히 고정된 계약 버전,
독립된 심사 A·B와 대응 대조 참조, 적용 판정, 개별 결과와 요약 근거를 담는다.
요구사항 판정은 원본 근거를 가진 별도 계약이며 원본이 요구하는 추가 증거를 소비할 수 있다.
최종 판정 결과가 없으면 미완료이며 성공으로 처리하지 않는다.
스키마 구조는 의미 증명·승인·실행 허가나 검증기 구현이 아니다.

## 아직 정의하지 않은 영역

Plan 공통 구조·식별·버전·단위, User Profile, 범용 README 템플릿과 Agent 관리의 필드는
이번 논의에서 정의하지 않았다. 해당 골격 8개는 `not: {}`로 모든 입력을 거부한다.
Plan 상태만 기존 상태 소유 계약을 참조한다. 미정 골격이나 기존 계약 참조 파일을
완성된 신규 설계로 취급하지 않는다.

후속 순서는 필드 검토 → 임시 검증기 구현 → 참조·원본 의미·범위·선택·증거 검증
→ 선택된 정책의 신규 계약 이전 → 후속 단계에서 이전 검증기 제거다.
