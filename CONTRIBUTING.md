# Contributing to PTSIP

PTSIP is currently a draft specification.

## Contribution categories

Changes should identify one category:

- editorial;
- clarification;
- normative addition;
- normative breaking change;
- schema change;
- conformance change.

## Normative changes

A normative change should:

1. identify affected rule IDs;
2. explain the architectural problem;
3. describe compatibility impact;
4. update the registry when rule metadata changes;
5. update conformance requirements when necessary;
6. add or update an ADR for material architecture decisions.

## Terminology

Do not use `PTSIP` alone to imply a global industry standard. In introductions, prefer the full expansion **Product–Toolchain SDK Isolation Policy**.

## Examples

Examples must not silently weaken normative rules. If an example uses an exception, label it explicitly.
