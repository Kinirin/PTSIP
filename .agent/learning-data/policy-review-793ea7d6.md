# Support Feature 관찰 사례 17건의 정책 검토 초안

2026-11-08 검토 기준 리비전은 `793ea7d65bda06de77c938a2b2795ad442920746`이다. 관찰에 연결된 Support Feature 정책 14개에서 원본 규칙 17개를 찾았다. 아래 원문 해석은 각 규칙의 요지다. **관찰**은 선택과 그 기록에서 확인되는 범위다. **AI 검토안**과 **질문**은 새 정책을 결정하기 위한 초안이며 정책 작성, 계약 등록, 평가, 실행의 권한을 부여하지 않는다. [작업 결정](../../.ptsip/tasks/observation-learning/decision.json), [관찰 원본](../../.ptsip/tasks/observation-learning/observations.json), [로컬 후보 데이터](./observation-candidates.jsonl)

정책 원문 위치는 해당 문서의 `Policy_Content.items`에 있는 `SRC-*` 항목이다. 17개 항목 모두 원본의 `/authority_semantics/family_definition/kernel_definitions/{index}` 아래에 있다. RISK와 SUPPLY 두 사례의 문서는 `DRAFT`이고 나머지 15개 사례의 문서는 `ACTIVE`다. 상태는 기준 리비전에서 읽었다. 관찰 17건 중 4건은 대화 요약에서 복구됐고 13건은 사용자 메시지에서 직접 기록됐다. 직접 기록 중 5건은 선택 문자만 남아 있어 당시 질문과 선택지 문구를 확인할 수 없다. 해당 행에는 기록된 주석과 답변 자체를 구분했다.

## 2. 책임 참조, 실패 응답과 검증 결과

CHANGE의 책임 배분이 실패 응답과 증거 판정에 어떤 입력을 주는지 검토한다. ASSURE의 세 결과는 CASE-003에서 먼저 검토하고 CASE-016에서 빌드 증거에 적용한다. CASE-009의 쓰기 원자성은 증거 판정과 별개로 결정할 항목이다.

### CASE-004 승인 이력

이 사례는 D를 선택한 대화 요약에서 복구됐고 `ALTERNATIVE_OWNERSHIP_DIRECTION`으로 기록됐다. 승인 전 CHANGE는 호환 입력, 선행 검증, 레거시 폐기 조건을 정한다고 읽혔다. 별도 승인 커밋 `87db24285d75f74c4a5ca47d45fedf19dc800bad`는 CHANGE가 이관 경로와 호환 범위를 맡고, 검증·폐기에 필요한 책임을 등록된 RA 식별자로 참조하도록 두 원본 항목 `SRC-0005`, `SRC-0009`를 바꿨다. 폐기 조건, RAC 연결, AEC 권한 행사 조건은 RA 책임 선언에서 관리한다. 그 커밋의 정책 파일 내용은 검토 기준 리비전에서도 동일하다. [승인 커밋](https://github.com/Kinirin/PTSIP/commit/87db24285d75f74c4a5ca47d45fedf19dc800bad), [CHANGE 현재 문서](../../src/policy/CHANGE/SFP-CHANGE-0001.yaml)

승인 변경은 문서의 책임 배분에 해당한다. 규칙별 RA/RAC/AEC 바인딩은 `UNRESOLVED`이고 [RA 목록 계약 등록 자료](../../.ptsip/contracts/compile-sealed-rbac/Responsibility/RA_list_contracts.json)의 활성 상태는 `UNREGISTERED`다. 아래 CASE-004 질문은 그 승인 범위에서 아직 특정되지 않은 참조를 다룬다.

## 기계 검증에서 사용할 근거

관찰 파일과 로컬 후보는 사례 ID, 정책 경로, 규칙 ID, 원본 항목을 대조하고 근거의 출처와 미결정 상태를 보존하는 데 사용할 수 있다. 현재 적용성 등록은 규칙 내부의 명시적인 근거와 정확한 계약 참조를 요구한다. 위 자연어 해석이나 여러 사례에서 반복된 선택만으로 RA/RAC/AEC 적용 여부를 채울 수 없다. 각 사례에 필요한 참조가 검토에서 결정되면 해당 규칙과 계약의 정확한 항목 및 리비전을 별도 변경에서 확인한다.
