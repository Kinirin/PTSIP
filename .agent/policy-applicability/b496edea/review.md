# 정책 적용 판단 사용자 검토

기준 main b496edea09d4574d242df43d27e3bcd495d6d1ca. 이 문서의 선택지는 사용자 검토를 위한 초안입니다.

기존 규칙의 자연어 해석과 관찰 출처는 [사례별 원문 검토](../../learning-data/policy-review-793ea7d6.md)에 있습니다.

적용 판단 미해결 2,001개와 생명주기상 비대상 1,269개를 구분했습니다. 아래 7개 묶음은 관찰 자료가 연결된 범위의 결정 후보입니다.

## REV-01 금지 조건과 PTSIP 밖의 작업

CASE-010

기존 NORM 규칙은 연결된 Specification의 MUST_NOT을 프로젝트 정책이나 요청으로 약화할 수 없다고 읽힙니다. 사례의 앞부분은 차단과 사용자 통지를 설명하지만, 마지막의 ‘자동 우회 권한’이 가리키는 작업 범위는 미결입니다.

- **A** PTSIP는 차단과 사유를 기록하고, 이 정책에서 별도 작업 절차는 정의하지 않습니다.
- **B** PTSIP 차단은 유지하고, 재확인한 요청을 PTSIP 밖에서 별도로 접수하는 절차만 검토합니다. 별도 작업의 권한과 실제 실행은 별도로 판단합니다.

PTSIP 내부의 예외를 의도했다면 두 안에 포함되지 않으므로 해당 예외의 권위·범위·조건을 별도로 명시해야 합니다.

## REV-02 작업 범위, 소유자 위임, 위험 수용

CASE-007 · CASE-008 · CASE-011

INTENT의 작업 범위는 필요한 변경을 식별하는 기준입니다. GOV 사례는 타 소유자의 책임을 사용할 조건과 그 소유자의 결정 권한을 구별합니다. RISK 문서는 DRAFT이고 사례 007·011에는 선택 문자만 남아 있습니다.

- **A** 작업 범위와 관계없이 소유자 판단이 필요한 변경은 기존 소유자에게 요청합니다.
- **B** 기존 소유자의 명시적 위임이 있을 때만 위임된 판단을 검토합니다. 책임의 사용·참조와 변경·결정, 그리고 위험 수용의 범위를 각각 지정합니다.

B라면 위임의 주체, 행위, 대상, 리비전, 기간과 위험 수용 한도를 각각 결정해야 합니다.

## REV-03 CHANGE 책임 참조와 CNTR 오류 결과

CASE-004 · CASE-006

별도 승인된 CHANGE 규칙은 검증·폐기 책임을 등록된 RA로 참조하는 방향을 선언합니다. 구체적인 RA 항목·리비전은 아직 없습니다. CNTR 사례는 실패 응답의 상세 내용에 관한 별도 결정입니다.

- **A** 실패 응답에 실패 이유와 정확한 책임·조건 리비전 참조를 제공합니다.
- **B** 실패 원인 판단에 필요한 조건을 응답에서 읽을 수 있게 하고, 상세 항목의 공개 범위와 정확한 리비전 참조를 함께 정합니다.

두 안 모두 승인된 CHANGE 방향을 다시 결정하지 않습니다. RA 항목 선택, 등록 및 책임 변경은 정확한 원본과 별도 승인이 필요합니다.

## REV-04 재시도와 읽기 전용 대조

CASE-001

OPS의 기존 규칙은 같은 작업 ID와 예상 리비전으로 재시도하거나 결과를 대조하는 문맥입니다. 요약 복원 응답은 오류 처리 도중 권한 조건이 바뀔 수 있음을 지적합니다.

- **A** 실제로 다시 쓰기 전에 권한 행사 조건을 확인하고, 이전 시도의 읽기 전용 확인은 별도 절차로 다룹니다.
- **B** 재확인을 촉발할 변경 신호와 그 신호의 검증 근거를 먼저 정합니다. 신호나 근거가 불명확할 때의 처리는 별도 결정으로 둡니다.

권한 조건의 원본과 검증 책임자는 현재 사례에서 식별되지 않습니다.

## REV-05 쓰기 단위, 실패 무결성과 근거 적합성

CASE-003 · CASE-009 · CASE-016

REAL의 쓰기 단위와 ASSURE의 산출물·근거 연결은 서로 다른 검증입니다. CASE-003은 Family와 RA 역할 설명이 부족해 보류됐고, 009·016은 선택지 전문이 없습니다.

- **A** 쓰기 단위의 선언 주체와 실패 범위를 먼저 확인하고, 산출물·근거 판정은 기존 상태로 보류합니다.
- **B** ASSURE와 RA 책임 및 필요한 증거를 먼저 설명하고, 증거 부족과 위반을 구별하는 기준을 검토합니다. 쓰기 단위는 별도 결정으로 둡니다.

두 결정은 순서를 선택하는 안입니다. 어느 하나를 정해도 다른 검증 책임이나 CASE-003의 답은 자동으로 확정되지 않습니다.

## REV-06 최신 원본, Projection과 결정 기록

CASE-002 · CASE-005 · CASE-017

INFO에는 과거 정보 모델과 원본·파생 정보 관계가 있고, RECORD 사례는 정책 결정의 기록과 당시 책임 근거의 추적을 함께 언급합니다. 최신 원본 우선과 구 Projection의 물리 삭제 여부는 별개입니다.

- **A** 현행 사용에서 낡은 Projection을 제외하고 과거 근거로는 보존합니다. 당시 책임은 확인 가능한 식별자와 리비전으로 추적합니다.
- **B** 현행 사용 차단과 별도로, 재생성·보존·정리 조건을 정의합니다. 과거 정보 축을 유지할지 새 모델로 바꿀지는 별도 결정합니다.

어떤 소유자의 어느 등록 원본을 최신으로 인정할지, 결정 기록과 기술 추적의 경계를 각각 정해야 합니다.

## REV-07 공급 범위, 소유자 메타데이터와 보안

CASE-012 · CASE-013 · CASE-014 · CASE-015

DRAFT SUPPLY의 외부 산출물·근거 문맥과 사용자 제작 확장 중심 응답 사이에 범위 차이가 있습니다. ARCH의 라이프사이클 책임, CTRL의 실행 전 확인, RECORD의 기록 분류도 구별해야 합니다.

- **A** SUPPLY를 사용자 제작 확장 중심으로 검토하고, 다른 공급물의 출처 기록은 별도 책임으로 결정합니다.
- **B** 사용자 확장을 더 넓은 공급·출처 범위에 포함하는 방향을 검토합니다. 소유자 정보와 보안·실행 권한은 별도 근거로 판단합니다.

정확한 계정 정보 출처, 공동 소유자와 변경 확인 기준, 기술 감사 기록 요건을 각각 결정해야 합니다.

정책 변경을 검토할 때 대상 규칙과 기존 값, 정확한 변경안과 근거를 고정합니다. 적용 선언은 정확한 등록 소유자·항목·리비전이 필요합니다. 비적용 선언은 해당 규칙 자체의 명시 근거가 필요합니다.
