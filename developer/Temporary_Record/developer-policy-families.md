# 작업 기록 — 신규 개발 정책과 Root Family

기록 시작: 2026-10-17  
작업 상태: 정식 정책 구조 개혁 중, 개별 패밀리 구현 완료 여부 미확인

## 목적과 책임

`developer/policy/{FAMILY}/`에 앞으로 들어갈 PTSIP **개발 정책**을 신규 계약에 따라 작성하는 작업 범위를 정리한다. 정책 데이터는 YAML 형태를 의도하며, 허용되는 필드 구조·값은 신규 `developer/contracts/schemas/`에서 정의하는 방향이다. 어떤 패밀리가 무슨 정책을 소유하고 어떤 필드를 요구할지는 사용자 검토 전에 추론하지 않는다.

## 작업 대상과 경계

- 목표 정책 위치: `developer/policy/ARCH/`, `GOV/`, `INFO/`, `RECORD/` 등 Root Family별 디렉터리
- 검증 계약의 설계 위치: `developer/contracts/schemas/`
- 14개 Root Family 체계는 폐기하지 않았으나, 현재 전면적인 패밀리 구현은 **잠시 중단**한 상태이다.
- 목표 정책 디렉터리의 기존 파일과 이전 정책 계약은 새로운 정식 정책 권위로 자동 채택하지 않는다.
- 특정 신규 스키마의 존재만으로 이에 대응하는 정식 패밀리 정책이 구현·검증되었다고 판단하지 않는다.

## 확인된 사용자 결정과 간단한 이유

- 장기적으로 사용자 권위를 담을 대상은 `developer/policy/`의 신규 정식 개발 정책이다.
- Root Family에 따라 허용 값과 규칙이 다를 수 있다. 하나의 예제 구조를 모든 패밀리에 복제하지 않는다.
- 과거 유용한 정책 의미는 사용자 검수 뒤 새로운 계약 구조로 재채택할 수 있지만, 이전 의존성을 강제하지 않는다.
- 임시 작업 규칙은 정식 정책이 해당 역할을 대체할 수 있을 때 사용자가 전체 대체를 판단한다.

## 마지막 확인된 작업 지점

신규 개발 정책의 상위 목표와 14개 Root Family 보류 상태는 사용자 설명으로 확인했다. 신규 패밀리별 YAML 정책의 완성 여부, 신규 검증기의 존재 및 실행 성공은 확인하지 않았다.


## 남은 작업과 우선순위 조회

기계적으로 관리하는 남은 작업·우선순위·선행 조건은 [`pending-work.json`](pending-work.json)에서 확인한다. 작업 진행의 확인 지점과 사용자 결정은 이 파일에서 유지한다.

이 기록은 패밀리별 정식 정책을 대신하지 않으며, 임시 폴더 전체 삭제 시 함께 정리될 작업 기록이다.
