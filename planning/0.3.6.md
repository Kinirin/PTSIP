Future sub-stage documents MUST NOT be pre-created.

Required process:

```text
current stage ACTIVE
    -> complete its declared implementation gate
    -> freshly read development branch HEAD
    -> record predecessor completion
    -> create next stage sub-document with exact entry SHA
    -> mark only that implementation stage ACTIVE
    -> begin only that stage
```

Rules:

1. only one WU-04 implementation sub-stage is ACTIVE at a time;
2. later stages remain `LOCKED` until the predecessor implementation gate is complete;
3. a future sub-document is created only at actual stage entry;
4. every sub-document records predecessor and exact entry baseline SHA;
5. implementation must not jump ahead because a later integration is convenient;
6. sequencing changes are recorded here before entering an affected stage.

## 3. Canonical architecture boundaries

Canonical PTSIP lifecycle classifications remain exactly:

```text
PRODUCT

```

These axes remain independent:

```text

    = primary lifecycle ownership

    = coarse responsibility characteristics

relationships
    = project-owned typed directed semantics

source_mode / derived origin
    = declaration authority provenance

VPMS Verification Purpose
    = what verification protects/verifies
```

Canonical Responsibility Map source modes are:

```text
explicit
template
hybrid
```

The accepted declaration/materialization authority boundary is recorded in `decisions/ADR-0009-responsibility-map-declaration-authority.md` and normatively frozen by `PTSIP-RMAP-013` through `PTSIP-RMAP-017`.

Materialization is deterministic and non-authoritative. Template selection is explicit and revision-bound. Hybrid precedence is stable-ID whole-entity replacement/extension/removal over the selected immutable template declaration.

WU-04G does not weaken those rules. `PTSIP-RMAP-017` now states that an **accepted project-owned clarification/adoption decision** may authorize the exact hybrid project extension/replacement and, when necessary to represent that decision, the source-mode transition `template -> hybrid`. Repository evidence and the materializer remain non-authoritative and cannot trigger this transition by themselves.
