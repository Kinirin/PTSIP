Canonical lifecycle classifications are exactly:

```text
PRODUCT

```

`TOOLCHAIN` is a Tool `0.3.5` legacy classification only. It is not a canonical Tool `0.3.6` classification or alias.

These axes remain independent:

```text

    = primary lifecycle ownership

    = coarse responsibility characteristics

    = project-owned typed directed semantics

```

Canonical Responsibility Map source modes remain:

```text

hybrid
```

Template selection is explicit and immutable-revision-bound. Materialization is deterministic and non-authoritative. Repository evidence, template materialization, and discovery MUST NOT become architecture authority.

PTSIP lifecycle classification and VPMS Verification Purpose remain independent.

## 9. Specification binding contract

For Tool `X.Y.Z`:

```text
Tool X.Y.Z
    -> Specification X.Y.Z-draft
    -> immutable SPEC_REVISION
```

Current Tool `0.3.6` binding:

```text
Specification: 0.3.6-draft
SPEC_REVISION: d6995ed232e845b88d8235b851e80ab54b7804ea
```

A new immutable Specification revision is required only for a genuine normative change. Regression closure, test migration, dogfood execution, or documentation-only release preparation must not move `SPEC_REVISION` by themselves.

WU-04I and WU-05 did not require a normative revision change.
