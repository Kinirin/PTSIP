## 1. Planning replacement

Tool `0.3.7` replaced the cancelled `0.3.6.1` planning family. The retained migration concepts were strengthened with deterministic source-generation discovery, evidence normalization, compatibility readers, explicit migration obligations, deterministic target deltas, and guarded mutation/promotion.

Tool `0.3.7` also establishes explicit separation between Tool SemVer, Project Profile contract identity, Specification binding, and one concrete Project Profile instance revision.

## 2. Independent version identities

PTSIP treats these as independent axes:

```text
Tool Version
    0.3.7

Project Profile Contract Version
    pp.1.01

Specification Binding
    0.3.7-draft @ immutable revision

Project Profile Instance Revision
    immutable revision/content identity of one concrete declaration
```

The following implication is invalid:

```text
Tool 0.3.7
    => Project Profile 0.3.7-draft
```

Likewise, a PP contract change does not require a Tool version change when the same Tool already supports that contract.

ADR-0019 defines the PP namespace:

```text
pp.<major>.<minor>
```

and the governing major rule:

> **Project Profile major version은 governing lifecycle classification의 집합 또는 그 classification semantics가 변경되어 기존 프로젝트의 lifecycle 재분류를 요구할 수 있을 때 상승한다.**

Within one major generation, PP minor changes represent contract-semantic or structural changes such as components, relationships, associated artifacts, policies, and Responsibility Map declaration/authority semantics. Ordinary repository-specific declaration edits remain instance revisions and do not bump the PP contract version.

ADR-0023 extends the independent-identity model with an explicit typed Specification binding:

```text
SpecificationBinding
    family
    source
    immutable revision
```

The Project Profile contract identity MUST NOT be used as an implicit Specification family field.

## 4. Migration-control model inherited from ADR-0010

The 0.3.7 migration engine retains these core rules:

- evidence and inference are not architecture authority;
- source generations are analyzed independently;
- Required Work Elements alone contribute to source completion;
- Removal Migration Elements have no preservation obligation;
- Asynchronous Work Targets do not contribute to completion;
- accepted target declarations accumulate as target state, not inherited source-category metadata;
- conflicts fail closed or require explicit owner resolution;
- sources converge directly on the selected Final Point rather than chaining through completed intermediate profiles;
- temporary sources may be removed only after verified completion;
- canonical source is handled last;
- promotion requires exact snapshot/global validation;
- mutation is restricted to accepted semantic deltas;
- interruption/recovery remains ledger-bound and fail closed.

WU-10 replaced Tool-numbered target-generation assumptions with independent PP-aware direct convergence while retaining legacy Tool-numbered paths only as historical/continuity aliases where explicitly authorized.

ADR-0023 further narrows historical bridge responsibility: historical bridges remain migration interpretation authority and MUST NOT become the generic validator's Specification-support registry.

## 5. Evidence and authority pipeline

```text
profile-generation inventory
    -> repository facts
    -> candidate discovery
    -> normalized evidence + provenance
    -> source compatibility reader
    -> source-specific obligation evaluation
    -> migration analysis
    -> target proposals
    -> deterministic plan
    -> project-owner confirmation
    -> exact snapshot validation
    -> safe apply
    -> guarded promotion
```

Authority boundary:

```text
Evidence != Authority
Inference != Authority
Proposal != Authority
Tool release version != PP migration authority
Migration capability != repository adoption authority
Specification support != historical migration authority

accepted project-owned decision
    -> exact authorized target delta / adoption action
```

- typed boundaries and state;

- independent focused verification;
- fail-closed handling of unknown/ambiguous identities;
- later WUs consuming earlier contracts instead of duplicating them;
- no Tool/PP/Specification/version-instance coupling.
