## 1. Why Tool 0.3.5 continues after WU-19

The coding-agent evaluation performed after WU-19 found a release-relevant usability gap: the PTSIP repository itself had no root `ptsip.yaml`.

Without a repository-owned Project Profile:

- `ptsip validate .` reports no project profile;
- discovered component candidates remain evidence without a project-owned responsibility declaration;
- `ptsip gate` must request responsibility facts that this repository already knows about itself;
- VPMS self-adoption Target IDs are not backed by repository PTSIP component metadata;
- coding agents gain purpose-preserving VPMS semantics, but PTSIP cannot supply a durable self-description of the repository whose work they are planning.

This is treated as a Tool `0.3.5` completion issue rather than deferred to `0.4.0`.

The earlier WU-18 verification remains valid evidence for the code/distribution state it tested, but it is no longer the final verification of the latest branch HEAD after this extension.

## 2. WU-20 — Repository Self-Profile

**Status:** `COMPLETE`

**Depends on:** `WU-19`

### Responsibility

Add and verify the repository-owned root `ptsip.yaml` so PTSIP can describe its own Product, Toolchain, and Neutral Contract responsibilities without path-only inference.

### Required semantics

The self-profile MUST:

1. bind exactly to `0.3.4-draft @ b5b17dd16667cc1afaf1d23054b6e5dd773e3f5e`;
2. declare the distributed PTSIP core and VPMS library as Product-owned responsibilities;
3. keep embedded/canonical Specification contracts and repository architecture declarations non-executable and independently governed;
4. declare repository tests, release automation, CI/documentation automation, and repository maintenance as Toolchain responsibilities;
5. preserve the distinction between PTSIP component classification and VPMS Verification Purpose;
6. give each currently discovered component candidate exactly one covering declared component so clarification is not generated merely because the repository lacked a self-profile;
7. keep the entire tracked repository partition free of equal-specificity ownership conflicts, unmatched selectors, and unassigned tracked files;
8. resolve the existing VPMS self-adoption Target IDs `ptsip-distribution` and `repository-release-automation` through the read-only PTSIP metadata bridge;
9. introduce no PTSIP-core dependency on VPMS and no authority mutation;
10. remain a project-owned declaration, not conformance proof.
